# Second-pass review

2026-09-28. Starting checkout `d6052b4`, plus the uncommitted changes documented here. The first pass produced an inventory and isolated prototypes, not application fixes. This review inspected the actual application and implemented the necessary corrections. Existing typography, colors, imagery, cards and article hierarchy remain.

## Scope and evidence

One active Next.js app and 66 page templates, independently inventoried from `apps/web/src/app`. The inventory matches the previous route count, but the earlier review lacked intermediate-width coverage and implemented behavior. No authentication or role-specific UI exists. No shared UI package exists outside the web app. Generated files, dependencies and the unrelated untracked retired `apps/api/` directory are intentionally excluded and untouched.

Every template has a representative capture at 1440×1000, 390×844 and 768×1024. This is 198 template/viewport samples, plus three explicit unknown-deity 404 samples. Initial captures used the local development app; the final targeted journeys and recaptures used the final local production build. One initial artifacts/tablet timeout and one development-only Fenrir router error were superseded by successful production recaptures. `second-baseline.json` preserves initial observations; `second-focused.json` records recaptures. Screenshot contact sheets were visually inspected. Images still loading at capture are not proof that every asset loaded. Dynamic records and content variants were sampled, not exhaustively inspected.

The final app runs locally at http://127.0.0.1:3000. The older port 3011 preview is an isolated prototype and is not implementation evidence. Browser-local progress/bookmarks were used; newsletter success and failure responses were mocked. No deployment, production-data change, purchase or real newsletter submission occurred.

## Questions and fresh research

1. How should catalog query, filters and pagination survive a reading journey?
2. How should empty/unavailable search support recovery and keyboard behavior?
3. Does reference-heavy content need a different hierarchy or mobile navigation?

[Fresh research log](second-pass-references.md): five accessible references, including Art Institute of Chicago and Perseus as adjacent content products, plus MDN History API, WAI combobox guidance and cmdk documentation. Scaife's protection page was explicitly excluded. Entries and screenshots were recorded before opening the next reference. Research supports retaining the existing visual identity, article hierarchy and image-led discovery. Documentation supports the behavioral fixes; it does not establish usability outcomes or conversion gains.

## Limits and external side effect

This is not a fully verified app claim. Live WebGL, actual provider/email/payment integrations, assistive-technology sessions, every locale/record/branch, and forced crash boundaries remain outside demonstrated browser coverage. No known reproducible critical/high issue remains in the exercised local journeys after final verification. The transient image optimizer delay's underlying cause is unconfirmed.

The first production build unexpectedly invoked the repository's configured Sentry source-map upload. The user was informed immediately, that build was stopped, and subsequent builds used an empty upload token. This was an unintended external side effect; it did not deploy the application. No further external writes were made.
