# Authentication review

Reviewed 2026-09-28 against the current local Mythos checkout, including the existing uncommitted design-review changes. Those changes were preserved. The user delegated the decision whether accounts fit this app.

## Decision

Keep the current account-free architecture. Mythos is a public encyclopedia; bookmarks, reading progress, quizzes and review history use browser-local storage, with explicit backup/export support. There is no existing authentication library, user database, private account area or paid entitlement to repair. Adding Google/GitHub login without a concrete account-backed capability would add infrastructure and data-handling obligations without making those existing features work better.

This is a product/engineering judgment grounded in the current code, not evidence that readers never want cross-device sync. Revisit accounts if that capability becomes an approved requirement. Google and GitHub are intentionally not implemented, rather than implemented and awaiting credentials.

No application changes were necessary for the authentication scope. The deliverables are this verified inventory, browser evidence and setup decision. No placeholder login controls, unused credentials or speculative database were introduced.

## Architecture verified

- Active app: `apps/web`, Next.js 16.3.4, React 19.2.8, TypeScript 6.0.3. Node used: 22.23.1; repository pin: 22.22.2. pnpm 10.34.5. No installed application auth provider in [package.json](../apps/web/package.json).
- [README](../README.md) and [ARCHITECTURE](../ARCHITECTURE.md) describe static catalog data and browser-local learning state. The retired, unrelated untracked `apps/api/` directory is excluded and untouched.
- [Proxy](../apps/web/src/proxy.ts) handles canonical entity redirects, locale and CSP. Its locale cookie is not a login/session cookie. CSP nonces are not authentication credentials.
- [Bookmarks](../apps/web/src/providers/bookmarks-provider.tsx:37), [progress](../apps/web/src/providers/progress-provider.tsx:81) and [review](../apps/web/src/providers/review-provider.tsx:41) providers read/write local storage. Legacy progress identifiers are local migration identifiers, not verified identities or roles.
- No login/signup/logout/callback/recovery routes, account settings, user/profile tables, auth migrations, roles or account-protected server actions were found in the active app. Fictional deity profiles and study sessions are not user accounts or auth sessions.
- [Privacy copy](../apps/web/src/app/privacy/page.tsx:110) describes local storage; bookmarks and progress repeat this limitation and link to [backup controls](../apps/web/src/components/progress/LearningBackup.tsx).
- `.env.local` is ignored; only `.env.example` is tracked as environment configuration. Secret-bearing local files were not opened. `SENTRY_AUTH_TOKEN` is an upload credential, and `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` is a site-verification value; neither configures reader login.

## Documentation and limitations

Read the authentication guide bundled with installed Next.js 16.3.4 and the [current official Next.js authentication guide](https://nextjs.org/docs/app/guides/authentication) on the review date. It distinguishes authentication, session management and authorization and recommends supported libraries when auth is needed. No auth library was installed or upgraded. Provider-specific callback instructions are inapplicable without a chosen account architecture; no URLs or successful setup were fabricated.

No production login, real provider, MFA, account linking, mail delivery or role journey was tested because those account features do not exist. Preview deployment protection is a hosting concern, not reader authentication. No secrets, tokens, live emails, purchases, deployments or production settings were accessed or changed during this review.

No remaining user action is required for the selected account-free scope. See [setup.md](setup.md).
